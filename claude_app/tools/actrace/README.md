# ActTrace — Claude Desktop 행위 재구성

ChatTrace 가 "무엇을 말했나" 를 답한다면 ActTrace 는
**"누가 · 언제 · 무엇을 했나"** 를 답한다. 대화 내용 복원은 부수적이다.

```
ActTrace "D:\사건\CASE01.E01" claude-desktop/msix "C:\사건\CASE01-행위"
```

위치 인자 셋은 **이미지 · 환경 · 저장 경로** 순서다 (2026-10-05 팀 합의).
기존 형식도 그대로 받는다 — `ActTrace -i <입력> -o <출력> --profile <환경>`.

E01 을 그대로 준다. 마운트하지 않는다. 60 GB 이미지 기준 약 1분.

ChatTrace 를 **라이브러리로 import** 한다. 포크하지 않는다 — 포크하면
한쪽만 고치고 잊는다. 이미지 입력(E01/dd/vmdk)도 `chattrace.image` 를 쓴다.

## 대화 복원과 같이 쓰기

```
ChatTrace -i "D:\사건\CASE01.E01" -o "C:\사건\CASE01" --timeline
ActTrace  -i "D:\사건\CASE01.E01" -o "C:\사건\CASE01-행위" --conversations "C:\사건\CASE01"
```

`--conversations` 를 주면 두 가지가 더 나온다.

- **초안이 실제로 전송됐는지 대조** — "치다 만 입력" 을 가려낸다
- **메시지 UUIDv7 역산** — 대화별 입력 구간

## 옵션

| 옵션 | 뜻 |
|---|---|
| `-i, --input` | 수집물 폴더 또는 디스크 이미지 |
| `-o, --output` | 결과 폴더 |
| `--conversations <경로>` | ChatTrace 결과 폴더 |
| `--all-programs` | Claude 외 프로그램 Prefetch 도 전부 |
| `--partition N` | 이미지의 파티션 지정 |
| `--profile <이름>` | 환경 프로파일 (결과에 기록) |
| `-v` | 자세한 로그 |

## 출력

| 파일 | 내용 |
|---|---|
| `behaviors.csv` | 행위 판정 전체. **여기부터 본다** |
| `findings.csv` | 확정·유력만 |
| `program_runs.csv` | 실행 횟수 + 마지막 8회 시각 |
| `inferences.jsonl` | 행위 판정 (근거·반증·대안가설 포함) |
| `observations.jsonl` | **전체 파싱 결과.** 재분석의 출발점 |
| `artifacts.csv` | 아티팩트별 집계 |
| `problems.csv` | 못 읽은 것과 사유 |

## 구조

```
아티팩트 ──파싱──▶ observation ──추론──▶ inference
              (사실)                  (행위)
```

**섞지 않는 이유.** 법정에서 다투는 것은 거의 항상 추론이지 관찰이 아니다.
반대 의견이 나왔을 때 관찰은 그대로 두고 추론만 갈아끼울 수 있어야 한다.

| 모듈 | 줄 | 담당 |
|---|---|---|
| `schema.py` | 185 | Observation/Inference · 시각 규약 · 신뢰도 |
| `localstorage.py` | 250 | **1순위** — 이벤트 큐 · 장부 · 재방문 · 초안 |
| `prefetch.py` | 250 | MAM 해제 · SCCA · 실행 횟수/시각 |
| `applog.py` | 170 | **2순위** — 전이줄 · 계정 UUID 평문 |
| `identity.py` | 260 | plan-usage · 계정 디렉터리 · Cookies |
| `registry.py` | 250 | BAM · UserAssist |
| `install_order.py` | 120 | `$MFT` 엔트리 번호로 설치 순서 |
| `history.py` | 240 | 브라우저 접근 경로 |
| `content.py` | 180 | 업로드 `localPath` · 임시대화 · UUIDv7 |
| `rules.py` | 900 | 규칙 37종 |
| `app.py` | 250 | CLI · 출력 |

**파서는 행위를 모른다.** "무엇이 적혀 있다" 까지만 말하고, 그게 어떤
행위인지는 `rules.py` 가 판정한다. 파서 안에 행위 이름이 들어가면 규칙을
바꿀 때마다 파서를 고쳐야 한다.

## 신뢰도 — 조작적 정의

| 등급 | 판정 규칙 |
|---|---|
| `confirmed` 확정 | 아티팩트와 행위가 1:1 · 재현 누락 0 · 다른 생성 경로 없음 |
| `suspected` 유력 | 독립 아티팩트 2개 이상 일치 · 대안가설을 함께 적는다 |
| `presumed` 추정 | 간접 증거 하나, 또는 부재 추론 |
| `undecided` 판정불가 | 근거 자체가 성립하지 않는다 |

**넘을 수 없는 선 셋**

```
R-ABSENCE-01   부재 추론은 '추정' 을 넘지 못한다.
               없는 것은 여러 이유로 없다 — 정리작업 · 미생성 · 수집 누락 ·
               버전 차이 · 그 행위를 안 함. 구분 못 하면 '판정불가'.

R-MFT-ONLY     $MFT 시각만 근거면 '유력' 을 넘지 못한다.
               반복 기록 파일은 최종 시각만 남아 중간 행위가 사라진다.

R-TZ-UNKNOWN   타임존 근거 없는 로컬 시각은 '유력' 을 넘지 못한다.
               R-TZ-DERIVE-01 로 역산되면 승격.
```

## 검증

| 검증 | 결과 |
|---|---|
| 삭제 판정 | **3/3 적중 · 오탐 0** (정답지 대조) |
| 설치 순서 | 선행 분석의 `$MFT` 엔트리 번호 3개와 정확히 일치 |
| 이벤트 매핑 | 재방문 기록과 23ms·10ms 로 2/2 일치 |
| 실측 산출 | 관찰 635 · 추론 65 · 규칙 37종 |

**검증 안 된 것도 적어 둔다.** `page.new_chat_input_ready` → 새 대화 매핑은
정답 대조에서 1/4 만 근접했다. `유력` 을 넘지 않게 두고 대안가설을 붙였다.

## 한계

- **실행 시각은 마지막 8회만.** 실측 123회 중 61회(50%). 횟수는 온전하다.
- **"흔적이 없다" 와 "행위가 없었다" 는 다르다.** 업로드·임시대화 파서는
  완성돼 있고 이 데이터에 그 행위가 없었을 뿐이다.
- **앱 로그에 타임존이 없다.** 역산하되 짝이 하나면 `유력` 까지만.
- **토큰 값은 기록하지 않는다.** 쿠키는 이름과 시각만.
- 행위 07 수정 전 원문 대조, 행위 08 메모리는 미구현.

환경이 달라도 **표 하나는 똑같이** 나와야 서로 맞춰 볼 수 있다.

|---|---|

| `report.html` | 개요(환경) + 행위별 토글 + 같은 3열 표 |

### 아티팩트 등급

느낌으로 가르면 사람마다 다른 표가 나온다. 기계가 따질 수 있게 정의했다.

| 등급 | 정의 |
|---|---|
| **직접** | 그 아티팩트 **한 종류만으로** 확정(`confirmed`) 판정이 선 경우 |
| **보조** | 여러 아티팩트를 함께 봐야 하거나, 확정 아래 등급인 경우 |

한 아티팩트가 같은 행위에서 두 역할을 다 했다면 **직접**을 적는다.

이 4열은 **요약**이다. 어느 추론이 어느 관찰에서 나왔는지는
`behaviors.csv` 의 `supported_by` · `source_artifacts` 와
`observations.jsonl` 에 그대로 남는다 — 통일 열 때문에 추적성을 버리지 않는다.

화면 출력도 구획을 맞췄다 (`Command line:` `Source info:` `Artifact
collection:` `Analyzing user actions:` `Execution summary:`). 구획 이름을
영문으로 둔 이유는 다른 환경의 출력과 **줄 단위로 대조**하기 위해서다.
도구 고유의 한국어 상세는 그 블록 뒤에 따로 낸다. 파서가 흘리는 진행
로그는 `-v` 를 줄 때만 보인다.

# ChatTrace — 무엇을 말했나

## 사람이 먼저 여는 것

### `transcript.txt`
복원한 **대화 원문**. 이 도구의 결론이다.

- 대화별로 묶고, uuid 가 붙은 대화를 먼저, 미연결 조각 뭉치를 맨 뒤로
- 각 메시지에 `[human]` / `[assistant]` 와 시각이 붙는다
- **UTF-8 BOM** — 메모장·PowerShell 에서 안 깨진다
- 대화가 0건이면 미연결 조각만 나온다 (PRO01 이 그랬다)

### `report.html`
브라우저로 보는 **종합 보고서**. 더블클릭하면 열린다.

- **단일 파일**이다. 바깥 CSS·JS 를 안 쓴다 — USB 로 옮겨도, 망분리 환경에서도 열린다
- 복원 통계 · 대화 목록 · 타임라인 · 조각 표를 한 장에
- 보기 좋게 **고른 것**이다. 판단 근거는 `findings.csv` 와 원본이다
- 크기는 입력에 비례 — PRO01 36 KB, T7 177 KB, 삭제복원 실험 390 KB

## 표로 보는 것

### `findings.csv` — **25열**
복원 결과 **전부**. 조각 하나가 한 줄이다.

```
tier, item, confidence, state, status, store, view, rule, sender, index,
conversation, uuid, title, created_at, parent, file, offset, seq, key,
external, msg_count, declared_msgs, declared_bytes, decode, text
```

핵심 열만 보면 된다.

| 열 | 뜻 |
|---|---|
| `tier` | 1=구조 복원 · 2=파편 · 3=카빙 |
| `item` | `conversation` `message` `attachment` `fragment` `marker` … |
| `state` | `live` `deleted` `overwritten` `carved` — **삭제 여부가 여기** |
| `file` `offset` `seq` | 어느 파일 몇 번째 바이트에서 나왔나 |
| `text` | 복원된 본문 |

**빈 열이 많은 게 정상이다.** `confidence` `view` `rule` 은 tier 2·3 카빙이
있을 때만, `status` 는 `--baseline` 을 줬을 때만 채워진다. 입력마다 열이
달라지면 스크립트로 못 돌리므로 **항상 25열 고정**이다.

### `pairs.csv` — 6열
**질문↔답변 쌍.** 짝이 맞은 것만 들어간다.

```
conversation, title, state, prompt_at, prompt, response
```

- 답변이 날아간 질문, 대화 uuid 를 못 붙인 조각은 **안 들어온다**
- 발표·보고서에 그대로 붙이기 제일 좋다
- 대화가 복원 안 되면 0행 (PRO01 이 그랬다)

### `prompts.csv` — 25열 (findings 와 동일)
`findings.csv` 중 `item == 'prompt'` 인 것만 추린 것.

- **비어 있는 게 흔하다.** tier 1 이 잘 되면 카빙할 게 없어서 0행이 된다
- 삭제가 심한 입력에서 채워진다 — 삭제복원 실험에서 103건 나왔다
- **"답변은 사라졌는데 질문만 남은 경우"** 를 잡는 자리다

## 기계용

### `conversations.json`
대화·메시지 구조 **전부**. 다른 도구에 넘길 때 쓴다.

- ActTrace 가 `--conversations` 로 받는 게 이것이다
- BOM 없음 (JSON 파서가 BOM 에서 죽는다)

### `chain_of_custody.json`
입력 **파일별 해시**. 증거 동일성 근거다.

- 파일 경로 · 크기 · SHA-256 · 수정시각
- 입력 파일 수에 비례해 커진다 — T7 은 941 KB

### `chattrace.log`
실행 로그. 복원 리포트가 여기 그대로 남는다.

- 저장소별 레코드 수, 단계별 회수 건수, 복원율
- **UTF-8 BOM**
- 같은 폴더에 다시 돌리면 **덧붙는다** — 숫자가 두 벌 보이면 마지막 것을 봐라

## `--timeline` 을 줘야 나오는 것

### `deleted_when.csv` — 12열
**언제 지웠나.** 이 도구에서 제일 값나가는 표다.

```
conversation, title, state, last_message, deleted_after, deleted_before,
span_sec, confidence, note, key_kind, seq, evidence
```

- 삭제 시각을 **구간**으로 준다. 단일 값으로 단정하지 않는다
- `confidence` 가 `높음 (10초 이내)` `보통 (1분 이내)` `낮음 (1시간 이내)` `경계값 없음`
- T7 실측 — 730건 중 **398건이 10초 이내**, 중앙값 10초
- 행이 많다. 레코드 하나하나가 한 줄이라 대화 수보다 훨씬 많다

### `timeline.csv` — 7열
`$MFT` · LevelDB 시퀀스 · 앱 로그를 **시간순으로 엮은 것**.

```
time, source, kind, subject, detail, evidence, note
```

- 수십만 행이 될 수 있다 — 삭제복원 실험에서 3.9 MB
- 엑셀에서 `source` 로 거르고 보는 게 실용적이다

# ActTrace — 누가 언제 뭘 했나

## 팀 합의 통일 산출물 (2026-10-05)

환경이 달라도 **이 둘은 모양이 같다.** 다른 조가 만든 표와 그대로 맞춰 본다.

### `report.csv` — **4열 고정**

```
행위 분류, 아티팩트, 경로, 아티팩트 등급
```

한 줄 = **(행위 · 아티팩트 · 경로) 한 묶음**. T7 기준 61줄.

| 열 | 들어가는 값 | 예 |
|---|---|---|
| `행위 분류` | B코드 + **표준** 행위 이름 | `B02 로그인 (인증)` |
| `아티팩트` | 아티팩트 종류 | `localstorage` |
| `경로` | 그 아티팩트의 경로 | `app\Local Storage\leveldb` |
| `아티팩트 등급` | `직접` 또는 `보조` | `직접` |

**아티팩트 등급은 느낌이 아니라 규칙이다.**

| 등급 | 정의 |
|---|---|
| **직접** | 그 아티팩트 **한 종류만으로** 확정(`confirmed`) 판정이 선 경우 |
| **보조** | 여러 아티팩트를 **함께** 봐야 하거나, 확정 아래 등급인 경우 |

한 아티팩트가 같은 행위에서 두 역할을 다 했으면 **직접**을 적는다. 더 센
쪽을 적어야 "이 경로만 봐도 된다" 가 표에서 사라지지 않는다.

★ 이 4열은 **요약**이다. 어느 추론이 어느 관찰에서 나왔는지는
`behaviors.csv` 의 `supported_by`·`source_artifacts` 와
`observations.jsonl` 에 그대로 남는다.

### `report.html` — 통일 보고서

1. **개요** — 입력·지문·**환경**·도구 버전·실행 시각·결과 수, 그리고 등급 두 개의 뜻
2. **행위** — B코드별 토글. 펼치면 `아티팩트 | 경로 | 아티팩트 등급` 3열 표
3. 그 아래 ActTrace 고유 상세 — 시각 · 판정 등급 · 근거 수
4. 점(핀)을 누르면 근거 하나의 **경로**가 옆 패널에 뜬다. 복사 버튼과 `file://` 링크가 있다

- **단일 파일.** 바깥 CSS·JS 없음
- **아티팩트 내용은 싣지 않는다.** Cache·History 는 한 화면에 안 들어간다. 경로를 주고 직접 확인하게 한다
- 토글 제목은 **표준 행위 이름** — `report.csv` 의 `행위 분류` 와 글자가 같아야 두 표를 맞출 수 있다
- 크기 T7 기준 162 KB

## 사람이 먼저 여는 것

### `summary.txt`
**한 장 요약.** 제일 먼저 여는 파일이다.

```
입력 / 지문 / 환경 / 시작·종료 시각
관찰 N건 · 추론 N건 · 문제 N건
판정 등급   확정 · 유력 · 추정 · 판정불가
질문별      Q1~Q5
```

- 고정 서식 평문. 파싱용이 아니다
- **UTF-8 BOM**
- 맨 아래 한 줄이 이 도구의 태도다 — *판정불가는 실패가 아니다*

## 관찰 · 추론 2층

**사실과 해석을 섞지 않는다.** 이게 이 도구의 설계다.

### `observations.jsonl` — 1층
아티팩트에서 **읽은 사실 그대로**. 해석이 없다.

- 한 줄에 관찰 하나. JSON Lines
- 각 줄에 `source_artifact` · `source_path` · `source_locator` · `fact_type` · `fact` · `ts`
- `source_locator` 가 **파일 안 위치**다 — `000003.ldb+0x55B6 seq=186 key=...`
- 제일 크다. T7 에서 863줄 710 KB
- **반박에 답할 때 여는 파일이다.** "어디서 나온 소리냐" 의 답이 여기 있다

### `inferences.jsonl` — 2층
관찰을 규칙에 태워 얻은 **행위**. 기계용이다.

- `behaviors.csv` 와 같은 내용인데 `basis` 같은 기계용 필드가 더 있다
- `basis` 에 규칙이 무엇을 근거로 삼았는지가 적힌다
  (예: `compared_chars: 0` — 대조한 글자가 0이었다)

## 표로 보는 것

### `behaviors.csv` — **15열**
추론 **전부**. 판정불가도 포함한다.

```
id, question, behavior_id, behavior_name, confidence, when_from, when_to,
span_sec, actor, rule_id, when_basis, note, alternatives, supported_by,
source_artifacts
```

실제로 볼 건 여섯이다.

| 열 | 뜻 |
|---|---|
| `behavior_name` | 무엇을 했나 |
| `confidence` | `confirmed` 확정 / `suspected` 유력 / `presumed` 추정 / `undecided` 판정불가 |
| `when_from` `span_sec` | 언제 · 구간 길이(초). **0 이면 시점이 확정** |
| `source_artifacts` | 어느 아티팩트에서 나온 판단인가 — `mft` `prefetch` `bam` `localstorage` … |
| `alternatives` | **배제 못 한 다른 설명.** 이게 있으면 `confirmed` 를 못 준다 |
| `supported_by` | 근거 `obs:` id. `observations.jsonl` 에서 찾으면 바이트 위치까지 나온다 |

### `findings.csv` — 15열 (behaviors 와 동일)
`behaviors.csv` 중 **확정·유력만** 추린 것.

- 보고서에 쓸 것은 이쪽이다
- 판정불가·추정이 빠지므로 **한계를 보려면 `behaviors.csv` 를 봐라**

### `artifacts.csv` — 7열
아티팩트별 **요약**.

```
artifact, path, observations, ts_min, ts_max, parser, status
```

- `observations` 는 **변경 횟수가 아니라** 그 아티팩트에서 뽑아낸 사실의 개수
- `ts_min`~`ts_max` 로 **"이 아티팩트가 어느 시간대를 덮는가"** 를 본다
- 공백 구간이 있으면 그 시간대는 근거가 없다는 뜻이다

### `problems.csv` — 6열
**못 읽었거나 일부만 읽은 것.** 도구가 스스로 신고한 한계다.

```
id, source_artifact, source_path, parser, parser_status, parser_note
```

- `parser_status` 가 `ok` 가 아닌 것만 들어온다 (`partial` / `error`)
- **비어 있으면 다 읽었다는 뜻이다.** 좋은 신호다
- 이 파일을 빼지 않는 것이 이 도구의 원칙이다

## 실행 정보

### `run.json`
**무엇을 · 언제 · 어떤 입력으로** 돌렸나.

```json
{ "tool", "tool_version", "spec_version", "env_profile",
  "input", "input_kind", "input_sha256",
  "started_at", "finished_at",
  "observations", "inferences", "problems" }
```

- `input_sha256` 이 **재현성 근거**다. 같은 입력이면 같은 지문이 나온다
- 폴더 입력은 `dirdigest:` 접두어가 붙는다 (목록+크기 해시)
- BOM 없음

## 조건부

### `program_runs.csv` — 16열
실행 **횟수와 마지막 8회 시각**. Prefetch 가 있어야 나온다.

```
name, hash, run_count, recorded_runs, unrecorded_runs, pf_created,
full_path, run_1 … run_8, source_path
```

- `run_count` 는 **온전하다** — Prefetch 헤더의 누적 횟수
- `recorded_runs` 는 **시각이 남은 개수. 최대 8** — 윈도우가 그만큼만 보관한다
- `unrecorded_runs` = 둘의 차. 횟수는 세었지만 언제인지 모르는 실행
- T7 실측 — 118회 중 시각을 아는 건 59회, 정확히 50%
- **`-NoKape` 로 수집하면 안 나온다** (PRO01 이 그랬다)

# 읽는 순서

```
1  ActTrace/summary.txt        한 장 요약
2  ActTrace/report.html        행위 토글 · 아티팩트 등급 (브라우저)
3  ActTrace/report.csv         통일 4열 — 다른 조 표와 맞춰 볼 때
4  ActTrace/behaviors.csv      행위 판정 전부 (출처·대안가설 포함)
5  ActTrace/problems.csv       도구가 신고한 한계
6  ChatTrace/transcript.txt    복원된 대화 원문
7  ChatTrace/report.html       브라우저로 한눈에
```

반박이 들어오면 `behaviors.csv` 의 `supported_by` → `observations.jsonl`
→ `source_locator` 순으로 내려간다. 파일 안 바이트 위치까지 나온다.

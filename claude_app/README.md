# claude_app — Claude Desktop (Windows) 분석 모듈

담당 권찬결. 대상은 **Claude Desktop 앱**이다 (Electron, MSIX 설치 기준.
NSIS 설치본도 같은 경로 규칙으로 받는다).

도구는 둘이고 답하는 질문이 다르다.

| 도구 | 답하는 것 |
|---|---|
| **ChatTrace** | 무엇을 말했나 — 대화 원문 복원 |
| **ActTrace** | 누가 · 언제 · 무엇을 했나 — 행위 재구성 |

ActTrace 는 ChatTrace 를 **라이브러리로 import** 한다. 포크하지 않는다 —
포크하면 한쪽만 고치고 잊는다. E01/dd/vmdk 입력도 `chattrace.image` 를
그대로 쓴다.

## 폴더 구조

```
claude_app/
  tools/
    ActTrace.cmd        행위 재구성 진입점
    ChatTrace.cmd       대화 복원 진입점
    actrace/            ActTrace 패키지 (파서 8 · 규칙 39종)
    chattrace/          ChatTrace 패키지 — ActTrace 가 import 한다
      image/            E01 / dd / vmdk 직접 읽기 (마운트 안 한다)
    tests/              통제 테스트 17개
  demo_result/
    ActTrace_팀형식/     팀 합의 산출물 (S01 T8-pre) — csv · html · json
    ActTrace/           실측 산출물 11종 (T7, 10-10 판)
    ChatTrace/          실측 산출물 8종
  산출물-설명.md
```

`actrace` 와 `chattrace` 는 **별개 패키지 둘**이다. 한 폴더에 같이 있는
이유는 ActTrace 가 ChatTrace 를 라이브러리로 쓰기 때문이고, 포크해서
두 벌로 두면 한쪽만 고치고 잊는다.

## 돌리는 법

```
tools\ChatTrace.cmd <이미지|수집물> <환경> <저장경로>
tools\ActTrace.cmd  <이미지|수집물> <환경> <저장경로>
```

위치 인자 셋은 **이미지 · 환경 · 저장 경로** 순서다 (2026-10-05 팀 합의).
기존 `-i` / `-o` / `--profile` 도 그대로 받는다.

```
ActTrace.cmd "D:\사건\CASE01.E01" claude-desktop/msix "C:\사건\CASE01-행위"
```

설치할 게 없다. **표준 라이브러리만** 쓴다 (Python 3.8+). E01 은 마운트하지
않고 직접 읽는다 — 마운트는 관리자 권한과 ACL 문제를 부른다.

`ActTrace --conversations <ChatTrace출력>` 을 주면 초안이 실제로 전송됐는지
대조하고, 메시지 UUIDv7 로 대화별 입력 구간을 역산한다.

## 산출물

통일 합의분 둘.

| 파일 | 내용 |
|---|---|
| `report.csv` | **4열 고정** — 행위 분류 \| 아티팩트 \| 경로 \| 아티팩트 등급 |
| `report.html` | 개요(환경) → 행위별 토글 → 같은 3열 표 → 상세 |

**아티팩트 등급은 느낌이 아니라 규칙이다.**

| 등급 | 정의 |
|---|---|
| **직접** | 그 아티팩트 **한 종류만으로** 확정(`confirmed`) 판정이 선 경우 |
| **보조** | 여러 아티팩트를 **함께** 봐야 하거나, 확정 아래 등급인 경우 |

한 아티팩트가 같은 행위에서 두 역할을 다 했으면 직접을 적는다. 이 4열은
**요약**이고, 어느 추론이 어느 관찰에서 나왔는지는 `behaviors.csv` 의
`supported_by` · `source_artifacts` 와 `observations.jsonl` 에 그대로 남는다.

나머지 산출물 전부는 [산출물-설명.md](산출물-설명.md) 에 파일마다 열 수 ·
줄 수 · 크기까지 실측값으로 적어 뒀다.

### 2026-10-07 — 중복 관찰을 합친다 (KAPE dedup 함정)

수집물은 KAPE 와 robocopy 가 Claude 폴더를 **둘 다** 담는 일이 흔하다.
그러면 같은 LevelDB 를 두 번 읽어 같은 사실이 두 벌 생긴다.

**수가 부푸는 것으로 끝나지 않는다. 사실이 틀린다.** 식별자 없이 관찰을
순회하는 규칙이 없던 사건을 만든다 — 실측에서 `R-REPLY-TIMING-01` 이
응답을 8번이 아니라 **16번** 받았다고 냈다.

v1.4.0 부터 관찰 층에서 합친다. 경로만 빼고 전부 같으면 하나로 두고,
버린 쪽 경로는 `duplicate_paths` 에 남긴다 — 두 곳에서 나왔다는 것도
출처 정보라 지우지 않는다. 합친 수는 `run.json` 의 `merged_duplicates`
와 화면에 찍는다.

검증 — 같은 디스크 상태를 수집물과 E01 양쪽으로 분석했을 때

```
고치기 전   수집물 1,064  /  이미지 618     (차이 446 = 전부 중복)
고친 뒤     수집물   620  /  이미지 618     (차이 2 = NTUSER 하이브 수 차이)
```

## 알아야 할 것 — 앱 버전이 복원 범위를 가른다

**2.9939.x 부터 대화 본문이 로컬에 저장되지 않는다.** 도구 결함이 아니다.

| | 2.2553.1 | 2.9939.2 |
|---|---|---|
| `react-query-cache` | 17건 · 외부 블롭 931,101 B | **1건 · 44 B · `.blob` 폴더 없음** |
| 답변 본문 | 복원된다 (22,784자) | **0자** |
| 질문 본문 | 복원된다 | 초안 조각으로 **83.6%** (225/269자) |
| 대화 목록 | 11개, 제목·상태 전부 | **0개** |

**요금제가 아니라 버전이다.** 같은 2.9939.2 에서 무료 계정으로 다시 돌려
동일 결과를 얻어 변수를 갈랐다.

60 GB E01 을 섹터 단위로 **전수 탐색**해 확정했다 — 비할당 영역 ·
`pagefile.sys` 포함, 답변에만 나올 고유명사 19종을 UTF-8 · UTF-16LE 두 벌로.
걸린 것은 전부 오탐이었다. 지워서 못 찾는 게 아니라 **처음부터 안 적는다.**

본문이 없어도 **받았다는 사실과 시각**은 남는다. Local Storage 이벤트 큐의
`claudeai.message.sent` → `perceived_ttft` → `first_text` → `perceived_ttlt`
를 엮어 "첫 글자까지 1.7초 · 전체 79.7초" 같은 판정을 세운다 (`R-REPLY-*`).

## 2026-10-10 — 팀 통일 형식 (A코드 · 6열 CSV · HTML)

### 행위 코드 A00~A14

B01~B13 을 A00~A14 로 다시 갈랐다. 이름만 바꾼 게 아니라 **둘이 쪼개진다.**

```
B01 사이트 접속 · 설치 및 실행  ->  A00 설치 + A01 실행|사이트 접속
B11 대화/계정 데이터 삭제       ->  A11 대화 삭제 + A12 계정 삭제
```

쪼개지는 쪽은 B 코드만 보고 못 가른다. **규칙 단위로 붙인다** —
`$MFT` 엔트리 순서를 보는 규칙은 설치, Prefetch 실행횟수를 보는 규칙은
실행이다. 매핑은 `actrace/actions.py` 에 있고, 매핑에 없는 규칙은 버리지
않고 `(미매핑)` 으로 표시해 눈에 띄게 한다.

환경에 따라 이름이 갈리는 둘 — `A01 실행|사이트 접속`, `A14 플러그인|커넥터`.

| 파일 | 열 | 용도 |

```
시각 | 사용자 행위 | 아티팩트 | 경로 | 등급 | [내용] | 근거
```

**한 줄 = 판정규칙 1개 × 파일 1개.** 시각은 그중 가장 이른 것, KST.

들어 있어 복원된다.

### ★ `내용` 열은 뺄 수 없다

다른 조 표는 5열이고 근거가 원시값뿐이다. 우리는 거기에 `내용` 한 칸을
**더한다** — 빼는 게 아니라 더하는 것이라 그쪽 도구로 읽어도 안 깨진다.

```
내용   설치 4단계 순서 정상
근거   mft.records[obs:0847].stage="패키지 등록"; entry=198492; @entry=198492
```

표만 보고 판단할 수 있어야 보고서다. 근거만 늘어놓으면 원본을 다시 열어야
한다. 대조할 때는 `내용` 열을 빼고 보면 5열이 그대로 맞는다.

   ▸ A00 설치                      매칭 N건      ← 2단 중첩
       ▸ 2026-10-05 22:05:19.241 KST  매칭 N건

## 2026-10-13 — 팀 합의 산출물 4종

| 파일 | 내용 |
|---|---|
| `collected_artifacts.zip` | 원본 아티팩트 수집본 + `_collection_manifest.json` |
| `parsed_artifacts.json` | 파싱값 (schema 1.2). **근거가 가리키는 인덱스의 원본** |
| `LLM_Artifact_Report.csv` | 6열 팀 형식 |

근거는 다른 조와 같은 표기로 `parsed_artifacts.json` 의 자리를 가리킨다.

```
artifacts[27].records[19].local_path="C:\TestData\S01-chart.png"
```

한 `artifacts[i]` = (아티팩트 종류, 원본 절대경로) 한 쌍. 그 안의
`collected_path` 가 zip 안 경로와 1:1 로 맞는다 — 근거 → 파싱값 → 원본
파일로 끊기지 않고 따라간다. 생성 코드는 `actrace/bundle.py`.

HTML 근거 칸은 팀 v3 구성을 따르되 `rv-note`(한 줄 해석) 하나만 더한다.

```
R-UPLOAD-LOCALPATH-01              규칙 ID
  · 업로드 S01-chart.png                    ← rv-note (우리만)
  · local_path = C:\TestData\S01-chart.png
  · file_name = S01-chart.png
  ▸ 원본 근거 보기
```

## 2026-10-14 — 업로드 경로 끝의 `{` (업로드 8건 → 4건)

T8-pre 업로드 경로 33건 중 **10건이 `S01-chart.png{`** 였다. 같은 파일이
두 경로로 갈려 `R-UPLOAD-LOCALPATH-01` 이 **업로드 8건**을 냈다. 시나리오가
올린 파일은 4개다.

V8 직렬화에서 문자열은 `0x22 <길이 varint> <바이트>` 이고, 객체의 마지막
속성 뒤에는 객체 끝 태그 `{`(0x7B)가 붙는다. 정규식이 따옴표·제어문자에서만
끊어 그 태그까지 먹었다. 이제 **앞의 길이 바이트로 자른다** (127자 넘는
2바이트 길이 포함). 길이 바이트가 없는 JSON 은 손대지 않는다.

| | 수정 전 | 수정 후 |
|---|---|---|
| 업로드 경로 고유값 | 8 (`{` 붙은 것 4) | **4** |
| `R-UPLOAD-LOCALPATH-01` | 8건 | **4건** |
| 다른 규칙 | — | 변화 없음 |

로그아웃 뒤 데이터 3벌(T8 · E01 logout · E01 login)은 업로드 관찰이 0이라
영향이 없다. 통제 테스트 4개 추가 — 양성(끝 태그) · file_name · 2바이트
길이 · 음성(JSON).
